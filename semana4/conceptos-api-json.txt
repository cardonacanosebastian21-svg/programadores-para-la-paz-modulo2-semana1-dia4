Responde con tus propias palabras.

1. ¿Qué es una API?

Respuesta: es un conjunto de reglas y protocolos que permite que dos aplicaciones de software se comuniquen entre sí.

2. ¿Por qué se dice que una API permite comunicación entre cliente y servidor?

Respuesta: porque actúa como la interfaz o el "puente" estandarizado que traduce las peticiones de uno en acciones para el otro

3. ¿Qué hace la ruta GET /api/propuestas?

Respuesta: se usa exclusivamente para leer o pedir información. No cambia nada en el servidor, solo "trae" datos.

4. ¿Qué hace la ruta POST /api/propuestas?

Respuesta: es la encargada de recibir datos desde el cliente y guardarlos como una nueva propuesta en la base de datos del servidor.

5. ¿Qué hace express.json() en esta práctica?

Respuesta: Su función es actuar como un "traductor" automático para tu servidor.

6. ¿Qué hace JSON.stringify?

Respuesta: convierte un objeto de JavaScript en una cadena de texto (string) en formato JSON.

7. ¿Qué hace JSON.parse?

Respuesta: toma una cadena de texto (que esté en formato JSON) y la transforma en un objeto de JavaScript que el programa pueda manipular.

8. ¿Qué hace fs.readFileSync?

Respuesta: se utiliza para leer el contenido de un archivo de forma sincrónica.

9. ¿Qué hace fs.writeFileSync?

Respuesta: sirve para guardar o escribir datos desde tu programa hacia un archivo en el disco duro.

10. ¿Por qué este ejercicio todavía no es una base de datos?

Respuesta: es una simulación excelente para entender cómo fluyen los datos entre el cliente y el servidor.

11. ¿Qué significa validar campos antes de guardar una propuesta?

Respuesta: es el proceso de revisar y filtrar la información que envía el usuario antes de permitir que entre a tu base de datos o archivo.

12. ¿Por qué una API comunitaria debe responder con mensajes claros cuando falta información?

Respuesta: Responder con claridad es asegurar que esa conversación no se rompa por falta de entendimiento.
